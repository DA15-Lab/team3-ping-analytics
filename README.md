## 프로젝트 개요

익명 투표 소셜 앱 Ping의 서비스 데이터를 종합 분석해 이탈 원인을 진단하고, 유저 활성화와 수익화 방향을 제안한 프로젝트입니다.

### 문제 정의

- **유입과 이탈이 한 달에 집중**: 전체 가입자의 93.9%가 2023년 5월 한 달에 가입했고, 친구요청의 93.2%와 탈퇴의 63.4%도 같은 달에 몰린 것으로 확인됐습니다. 가입자는 급증했지만 활성 유저 비율은 가입 당일 0.63%에서 28일 후 0.04%까지 낮아져, 유입이 활성으로 이어지지 못했다고 판단했습니다.
- **가입이 늦을수록 낮아지는 잔존율**: 가입월이 늦은 코호트일수록 1개월 잔존율이 낮아지는 경향이 나타났습니다(피어슨 r = -0.83, p = 0.0004).
- **네트워크와 콘텐츠 공급의 동반 약화**: 탈퇴 사유 1위는 "함께 할 친구가 없어서"(20.45%), 2위는 "재밌는 질문이 없어서"(18.59%)였습니다. 연락처 초대 성공률이 22.87%에 그치고 질문세트 생성량이 93.3% 급감한 뒤 회복되지 않은 점에서, 두 사유가 실제 데이터와도 부합하는 것으로 보았습니다.
- **병목은 질문세트 배정**: 가입자의 95.86%가 친구요청을 보냈지만 질문세트를 배정받은 유저는 0.73%에 그쳐, 이 구간을 가입 후 이탈의 주요 병목으로 판단했습니다.

### 종합 결론

분석 결과를 종합하면, Ping의 지속적인 활성화를 위해서는 콘텐츠 공급, 초기 네트워크 형성, 유저 반응 기반 수익화가 하나의 순환 구조로 연결될 필요가 있다고 판단했습니다. 콘텐츠가 상호작용을 만들고, 상호작용이 재방문을 만들며, 높은 반응이 수익화로 이어지는 선순환을 만드는 것을 핵심 과제로 보고 아래 세 가지를 제안했습니다.

| 제안 | 내용 |
| --- | --- |
| 콘텐츠 공급 | 신규 질문을 지속 보충하고, 반응이 낮아진 질문은 교체해 콘텐츠 신선도 유지 |
| 초기 활성화 | 가입 직후 친구 상호작용과 투표를 자연스럽게 경험하도록 해 초기 네트워크 형성과 핵심행동 경험 강화 |
| 개인화·수익화 | 과거 반응 데이터로 반응 가능성이 높은 질문을 우선 노출하고, 초성 확인·답장 이후 추가 포인트 소비로 이어지는 접점 최적화 |

## 주요 결과

### PART 1. 초기 네트워크 형성과 신규 유저 활성화

- 서비스 이용 조건인 같은 학교 유저 40명을 달성한 학교는 70.2%, 미달 학교는 29.8%였고, 달성까지 걸린 기간의 중앙값은 8일로 나타났습니다.
- 학교 내 가입 순서 1\~20번째 유저의 초기 활성화율(D0\~D3)은 81.5%였고, 40번째 이후에는 약 95% 수준에서 포화하는 것으로 확인됐습니다. 일정 수준의 초기 네트워크가 신규 유저 활성화의 기반이 된다고 해석했습니다.
- 가입 직후 실제 친구 상호작용이 있었던 유저의 후속 활동률이 더 높게 나타났고, 그중 친구요청을 주고받은 유저의 활동 지속성이 가장 높았습니다. 학교에 유저가 존재하는 것 자체보다 실제 상호작용이 이후 활동 유지와 더 관련이 있다고 판단했습니다.
- 첫 핵심행동의 속도보다 초기 친구 연결과 실제 투표 경험의 깊이에 따라 후속 활동률 차이가 더 뚜렷하게 나타났습니다.

### PART 2. 투표 Give & Take 관계와 이탈 전 변화

- 2023년 4~5월에는 투표를 주고받은 유저의 리텐션이 받기만 한 유저보다 높았고, 두 그룹의 리텐션 차이는 통계적으로 유의한 것으로 확인됐습니다(p < 0.0001).
- 상호 투표 경험자는 미경험자보다 평균 친구요청 수가 1.6배, 평균 투표 수가 8.88배 많은 것으로 나타났습니다. 다만 두 그룹의 표본 수 차이가 큰 점은 해석 시 유의할 필요가 있습니다.
- 모든 활동 기간 그룹에서 Give와 Take는 피크 이후 이탈에 가까워질수록 함께 감소했고, 상호관계 비율도 줄어드는 경향을 보였습니다. 단기 활동 유저는 Take 우세 관계가, 장기 활동 유저는 Give 우세 관계가 늘어나는 것으로 나타났습니다.
- 이 패턴이 탈퇴 사유 1위("친구가 없어서")와 맞닿아 있다고 보고, 친구가 줄어도 혼자 참여하며 다른 학생들과 결과를 비교할 수 있는 밸런스게임 콘텐츠를 제안했습니다.

### PART 3. 질문 기반 유저 반응과 결제 연관성 분석

- 투표 결과를 수신한 기록 중 결과를 읽은 비율은 55.67%, 초성을 1개 이상 확인한 비율은 4.71%로 나타났습니다.
- 전체 3,901개 질문을 5개 카테고리로 분류해 비교한 결과, 초성 확인율은 우정·신뢰·관계 친밀도(7.92%)와 외적 매력·연애 호감(7.42%)이 나머지 카테고리(3.74~4.53%)보다 높았습니다.
- 초성 확인 개수가 많아질수록 두 카테고리의 비중이 59.3%에서 78.4%까지 커져, 추가 확인 행동이 이 두 카테고리에 집중되는 것으로 판단했습니다.
- 초성을 20개 이상 확인한 유저의 결제 경험률은 1~2개 확인한 유저(5.81%)의 약 3.4배로, 반복적인 초성 확인과 결제 경험 사이에 연관성이 있는 것으로 보았습니다. 인과관계가 아닌 연관성으로 해석했습니다.
- PING 답장은 대부분 초성 개봉 없이 발생해 별개의 반응 행동으로 판단했고, 유저 반응의 범위에 포함했습니다. 적극적으로 반응한 유저일수록 결제 경험률이 높게 나타났습니다.
- 초성 개봉 예측 모델은 개봉 가능성을 일부 식별할 수 있었으나, 개인화 타겟팅에 바로 활용하기에는 예측 성능에 한계가 있다고 판단했습니다.

## 전처리 모듈

`src/preprocessing.py`는 테이블마다 `clean_<테이블명>(path)` 함수를 제공하며, 정제된 DataFrame을 반환합니다. 원본 폴더 위치가 기본 경로와 다르면 `path` 인자를 직접 넘깁니다.

```python
from preprocessing import clean_accounts_user, clean_accounts_group

users = clean_accounts_user()
groups = clean_accounts_group(path='원본 CSV 폴더 경로')
```

| 함수 | 주요 처리 |
| --- | --- |
| `clean_accounts_user` | `gender`·`group_id` 결측 제거, `pending_chat` 음수 제거 및 1000 초과 값 상한 처리, `alarm_count` 238 상한 처리 |
| `clean_accounts_group` | 학년 1~3만 유지, 학급 0·41 제거, 유저가 없는 20반 제거 |
| `clean_accounts_school` | 학생 수 0이면서 실제 연결 유저도 없는 학교 제거 |
| `clean_accounts_nearbyschool` | 거리 정보가 비정상인 학교와 삭제 대상 학교 제거, 자기 자신 행 제거 |
| `clean_accounts_attendance` | 출석일 리스트를 파싱해 유저-출석일 단위(long)로 변환 |
| `clean_accounts_blockrecord` | 자기 차단 제거, 동일 시각 중복 차단 병합, 반복 차단 파생 변수 생성 |
| `clean_accounts_paymenthistory` | `id` 외 모든 컬럼이 같은 중복 행 제거 |
| `clean_accounts_userquestionrecord` | 날짜형 변환, `has_read == 0`이면서 `opened_times == 1`인 모순 행 제거 |
| `clean_accounts_friendrequest` | 날짜형 변환 (이상치 없음) |
| `clean_accounts_userwithdraw` | 사유가 `admin`·`test`인 운영·테스트 계정 제외 |
| `clean_accounts_user_contacts` | 검증 결과 이상 없음, 그대로 사용 |
| `clean_polls_question` | 필수 컬럼 결측 제거, 중복 질문 문구는 최초 생성 건만 유지 |
| `clean_polls_questionpiece` | 필수 컬럼 결측 제거, 투표와 스킵이 동시에 기록된 행 제거 |
| `clean_polls_questionset` | 상태값 정리, 오픈 지연 시간과 이상 여부 파생 변수 생성 |
| `clean_polls_questionset_piece` | 질문 세트의 문항 리스트를 세트-문항 단위(long)로 변환 |
| `clean_polls_usercandidate` | 날짜형 변환 (이상치 없음) |
## 협업 방식

- **작업 공유**: 매일 오후 5시에 각자의 작업 내용을 공유합니다.
- **진행 관리**: 협업 노션으로 프로젝트 일정과 진행 상황을 관리합니다.
- **노트북**: 각자 `notebooks/<이름>_analysis.ipynb`에서 작업하고, 공통으로 쓰는 전처리는 `src/preprocessing.py`에 함수로 모읍니다.
- **코드 동기화**: 작업을 시작할 때는 시작 셀로 최신 코드를 받아오고, 끝낼 때는 작업 저장 셀로 노트북을 저장한 뒤 커밋·푸시합니다.
- **전처리 검증**: 전처리 함수를 모듈에 옮길 때는 노트북에서 만든 결과와 모듈 함수의 결과가 같은지 확인합니다.
